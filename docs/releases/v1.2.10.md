# v1.2.10 — Coordinated Hex Abyss migration

The retained DHCP client now obtains its optional native socket implementation
from Hex `abyss_raw` 0.9.0 instead of a pinned sparse Git dependency on
`abyss_dhcp_socket`. Core Abyss declarations use the matching 0.9.0 release.
The native facade remains `Abyss.DhcpSocket.Native`; the adapter normalizes native
open success for the YellowDog socket wrapper, and missing-package checks now
name `:abyss_raw`.

The shipped products remain independent Management and Worker releases. The
retained DHCP client is excluded from both; neither product acquires the raw
package or DHCP native build. Worker still provides authoritative DNS only.

See [dependency and validation details](../phase1/abyss-raw-migration.md).

Verified locally on Linux with Elixir 1.18 / OTP 28:

- Published Hex dependency resolution, actual adapter strict compilation, native
  loading from `:abyss_raw`, and an explicit native consumer release with its NIF.
- 22 socket/adapter/upstream contract tests passed, and all 11 isolated DHCP/ARP
  packet and cleanup gates passed through the YellowDog adapter. Disposable
  namespaces were removed afterward.
- Both default products compiled with warnings as errors. Clean release
  architecture checks and 19 rejected dependency/artifact mutations passed.
- Management release smoke passed against disposable PostgreSQL; Worker release
  smoke passed real DNS UDP/TCP, reload, SIGKILL recovery, and stopped persistence.
- The Linux x86_64 archive passed its full clean Debian 12 container smoke,
  including optional-native exclusion, managed bootstrap and credential reuse.
  The Management export/offline Worker file gate passed. Format and strict Credo
  checks passed.
- Nix Worker build and NixOS VM acceptance passed: non-root DNS, persistent
  snapshots, module lifecycle, URL-only bootstrap and credential reuse.
- ConfigSpec: 15 tests passed. The broader Management suite ran 527 tests with
  six existing failures; all six reproduced on unchanged `abf8d7ec` in the two
  affected test files. They concern old UI navigation/form expectations:
  `logs_live_test.exs:138` and `ui_test.exs:110,220,253,260,286`. They were not
  modified by this dependency migration.
- Worker: the final full run passed 111 tests with zero failures and one skipped.
- Worker testing exposed an intermittent immediate stop/reopen directory-lock
  race in unchanged `LocalStore` code. A baseline probe using Abyss 0.8.1 without
  starting its runtime reproduced six `:directory_locked` results in 100
  immediate reopen attempts. The external `flock` process can outlive
  `Port.close/1` briefly. This migration does not repair that lifecycle boundary.

The native release above is an isolated adapter consumer, not the complete
retained DHCP client application. It does not enable DHCP in either shipped
product. ARM runtime and deployment to a target host remain unverified.
